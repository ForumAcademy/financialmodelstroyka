# План реализации в Claude Code (GitHub + Vercel)

Каждый этап — отдельная ветка и PR с preview на Vercel. Промпт копируется в Claude Code как есть. Этап не начинается, пока не принят предыдущий.

## Этап 0. Репозиторий

1. Создать пустой репозиторий на GitHub, подключить к Vercel (Import Project).
2. Скопировать содержимое этого пакета в корень, закоммитить в `main`.
3. Промпт:

> Прочитай CLAUDE.md и docs/00–02. Настрой монорепо pnpm: packages/spec, packages/engine, apps/web (Next.js App Router, TypeScript strict). Добавь GitHub Actions: python scripts/validate_spec.py, pnpm typecheck, pnpm lint, pnpm test. Ничего не считай — только каркас.

**Приёмка:** CI зелёный, preview открывается.

Настройка Vercel (один раз, делает владелец репозитория): Add New → Project → Import `financialmodelstroyka`, Root Directory = `apps/web`, остальное по умолчанию. После этого Vercel сам создаёт preview для каждого PR.

## Этап 1. packages/spec

> Реализуй packages/spec: загрузка data/*.yaml, zod-схемы для sources, parameters, capex_items, regions, formulas; генерация TS-типов с union-типом всех ID параметров и формул. Сборка должна падать, если в коде используется несуществующий ID. Тест: все source_ids существуют, у level 1–3 есть URL.

**Приёмка:** опечатка в ID в коде — ошибка компиляции.

## Этап 2. Ядро: TIME, TEP, LAND

> Реализуй в packages/engine модули TIME, TEP, LAND строго по data/formulas.yaml (F.TIME.*, F.TEP.*, F.LAND.*). Одна формула — одна функция с тем же ID. Каждая функция пишет trace (входы, выход). Тесты: example из YAML + reconciliation_targets TEP из tests/cases/derbenevskaya_legacy.yaml.

**Приёмка:** площади кейса совпадают с исходником (143 560,388 м², 28 971,6 м², 35 294,59 м²); норматив машино-мест = 2 785.

## Этап 3. CAPEX

> Реализуй F.CAPEX.* и справочник capex_items.yaml: ставка × база × индекс, правила графика uniform / s_curve / at_milestone / follow_smr / follow_sales / manual. Проверки SCHEDULE_SUM и BUDGET_EQ_CF. Режим совместимости: ручные квартальные ряды из capex_legacy.

**Приёмка:** сумма весов = 1 для каждой статьи; УДС и «Прочие СМР» попадают в CF.

## Этап 4. SALES + ESCROW

> Реализуй F.SALES.* и F.ESC.*: ограничение продаж остатком, цена = рынок × стадия, структура оплат, эскроу по каждой очереди, раскрытие через TIME.ESCROW_RELEASE_LAG_M после РНВ. Режим совместимости: квартальный темп и +2%/кв из sales_legacy.

**Приёмка:** в режиме совместимости выручка по типам совпадает с reconciliation_targets (итого 118 130 288 024,50); в обычном режиме ПСН продано ≤ запаса.

## Этап 5. FIN

> Реализуй F.FIN.*: собственное участие вперёд, лимит, выборка, ставка с К1/К2 (покрытие за t−1), капитализация процентов, погашение из эскроу и ДКП, комиссии, эффективная ставка через XIRR. Траектория ключевой ставки — из FIN.KEY_RATE_PATH.

**Приёмка:** долг и проценты на конец = 0; нет циклических зависимостей; пример F.FIN.RATE даёт 0,1385.

## Этап 6. TAX + CF + KPI + CHECK

> Реализуй F.TAX.* (режим НДС по таблице TAX.VAT_REGIME, экономия по ДДУ по письму Минфина от 28.07.2026, перенос убытков), F.CF.*, F.KPI.* (XNPV, XIRR, LLCR, LTC/LTV, пиковый капитал), F.CHECK.ALL. Любая неуспешная проверка блокирует отчёт и показывается на дашборде.

**Приёмка:** все пункты expected_differences_after_fix выполнены.

Этапы 1–6 завершают расчётное ядро. Дальше — многопроектный сервис: сначала список проектов и хранение, затем экраны проекта, экспорт, сценарии и версии.

## Этап 7. Главный экран и проекты

> Подключи Postgres (Neon через Vercel Marketplace) + Drizzle и вход по общему паролю (docs/01_architecture.md, «Доступ к сервису»: пароль из APP_PASSWORD, затем имя пользователя). Таблицы по docs/01_architecture.md: users, projects, project_versions (с kpi_summary), parameter_values, attachments, audit_log. Главная страница — список проектов: название, регион, класс, площадь участка, выручка, NPV, IRR акционера, маржа, статус, дата изменения, автор; поиск, фильтры (регион, статус, класс), сортировка по любому столбцу. Мастер «Создать проект», шаг 1: название, регион из data/regions.yaml, кадастровый номер, класс; региональные параметры подставляются из regions.yaml, пустые — обязательный ручной ввод. Действия: открыть, переименовать, скопировать, архивировать (с подтверждением) / вернуть из архива; удаления нет. Статусы и переходы — по docs/01_architecture.md. Сравнение 2–3 проектов. Сид: tests/cases/derbenevskaya_legacy.yaml → демо-проект «Дербеневская (демо)». Страница проекта на этом этапе — дашборд с ключевыми показателями из ядра.

Перед этапом владелец добавляет в Vercel переменные `APP_PASSWORD` и `APP_SESSION_SECRET` (инструкция — в PR этапа).

**Приёмка:** на главном экране можно создать, скопировать, открыть и архивировать проект; все действия пишутся в audit_log; показатели в списке совпадают с дашбордом проекта (тест: kpi_summary = ResultSet той же версии); демо-проект открывается; без пароля ни одна страница и API недоступны; в журнале указано имя автора; удалить проект нельзя, архивный проект открывается и копируется.

## Этап 8. Экраны проекта и паспорт показателя

> Сделай в apps/web: (1) мастер ввода проекта по разделам: общее, участок, ТЭП, вехи по очередям, бюджет, продажи, финансирование — с подсказками how_to_fill и выбором источника; для уровня 5 — обязательные автор/обоснование/диапазон; вложения уровня 4 — Vercel Blob; (2) страницы Исходные данные и источники, ТЭП, Бюджет, План продаж, Эскроу, Финансирование, Налоги, CF (месяц/квартал/год), Дашборд; (3) по клику на любое число — «паспорт показателя»: формула словами и через ID, rationale, rejected, дерево зависимостей, источники с кликабельными ссылками; (4) результаты F.CHECK.ALL на дашборде.

**Приёмка:** из любой цифры дашборда за 2 клика видна ссылка на закон/статистику/документ; режим «только чтение» для статусов «Утверждён» и «Архив».

## Этап 9. Экспорт в Excel

> Реализуй packages/export на exceljs по docs/01_architecture.md (раздел «Экспорт в Excel»): 14 листов (Обложка, Исходные данные, Источники, ТЭП, Бюджет, План продаж, Эскроу, Финансирование, Налоги, CF мес/кв/год, Дашборд, Проверки), живые формулы для итогов, ставка × база × индекс, остатков и агрегатов CF, столбцы «ID формулы» и «Описание», оформление (ввод — синий, формулы — чёрный, ссылки на листы — зелёный), закреплённые шапки, форматы рублей/долей/дат, графики на дашборде. Кнопка «Скачать в Excel» на странице проекта и в списке; имя файла «<Название ЖК>_финмодель_<дата>.xlsx»; экспорт пишется в audit_log. Тест сверки: кэш итогов = ResultSet до 1 руб., пересчёт LibreOffice (headless, в CI) = ResultSet до 1 руб., гиперссылки «Источников» кликабельны, нет ошибок #REF!/#VALUE!/#DIV/0!/#NAME?.

**Приёмка:** выгрузка демо-проекта и любого созданного проекта открывается в Excel без ошибок и предупреждений о восстановлении; итоги совпадают с сервисом до рубля; ссылки на листе «Источники» кликабельны; последний используемый столбец листа CF — последний месяц модели.

## Этап 10. Сценарии и чувствительность

> Добавь сценарии (базовый / оптимистичный / пессимистичный) и торнадо-диаграмму по параметрам уровня 4–5 в пределах их min–max. На дашборде — доля NPV, зависящая от экспертных параметров. Сценарий выгружается на Обложку Excel.

## Этап 11. Версии расчёта

> Версии: каждый расчёт, который пользователь сохраняет, — неизменяемый снимок в project_versions (входы + spec_version + результат). История версий проекта, сравнение двух версий (входы и показатели с разницей), выгрузка в Excel любой версии.

**Приёмка:** старая версия пересчитывается с тем же результатом по своей spec_version; сравнение показывает изменённые параметры и их источники.

## Перед первым боевым расчётом закрыть

Список формирует `python scripts/validate_spec.py` (раздел WARN). Ключевые:

- режим НДС по ПСН/машино-местам в ДДУ и ДКП — подтвердить с налоговым консультантом;
- налог на прибыль застройщика (экономия по ДДУ): подтвердить распределение затрат по очередям;
- формула и коэффициенты платы за ВРИ (Москва, 593-ПП) — выписать из текста акта;
- Кпер НЦС для нужных регионов — из таблицы 1 НЦС 81-02-01-2026;
- ставки земельного налога — по ОКТМО через сервис ФНС;
- пояснить у автора исходника: ТЭПы!C35 (149 281 м²) и ТЭПы!C49 (5 200).
